# 上线发布SOP（可勾选）

## 0. 发布前准备
- [ ] 确认代码分支与发布版本号（tag/commit）已冻结
- [ ] 确认数据库备份目录可写、磁盘空间充足
- [ ] 确认生产环境变量已配置：`SECRET_KEY`、`DATABASE_URL`、连接池参数
- [ ] 确认 `/health` 可访问并返回 `{"status":"ok","db":"ok"}`

## 1. 发布前备份
- [ ] 执行备份脚本：
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\db\mysql_backup.ps1 -User root -Password 123456 -Database pear_ticket
```
- [ ] 记录备份文件名（时间戳）
- [ ] 抽样验证备份文件可读取

## 2. 发布执行
- [ ] 停止旧进程
- [ ] 部署新代码
- [ ] 启动应用（生产方式）
- [ ] 检查启动日志中无异常堆栈

## 3. 发布后验证（冒烟）
- [ ] 健康检查通过：`GET /health`
- [ ] 登录/退出正常
- [ ] 工单列表查询正常
- [ ] 新建工单正常
- [ ] 更新工单状态正常
- [ ] 客户工单认领（单个/批量）正常
- [ ] 上传图片正常

## 4. 审计日志验证
- [ ] `admin_log` 中有本次操作记录（新增/更新/删除/认领）
- [ ] 日志 `desc` 包含 `req:<request_id>`
- [ ] `success` 字段与接口结果一致（成功=1，失败=0）

## 5. 回滚预案验证（最低要求）
- [ ] 在测试库完成一次恢复演练
- [ ] 源库与恢复库工单数量一致
- [ ] 抽样 3 条工单内容一致

## 6. 回滚触发条件（明确）
- [ ] 连续 5 分钟 `/health` 异常
- [ ] 核心功能（登录/工单创建/工单更新）不可用
- [ ] 数据写入异常或明显错乱

## 7. 回滚执行
- [ ] 停止新版本进程
- [ ] 回退到上一版本代码
- [ ] 必要时从备份恢复数据库
- [ ] 启动旧版本并验证 `/health` 与核心流程

## 8. 发布记录（留档）
- [ ] 发布人
- [ ] 发布时间
- [ ] 代码版本（commit/tag）
- [ ] 备份文件名
- [ ] 验证结果
- [ ] 是否触发回滚
